# ISMS(-P) 대응 메모

> 이 문서는 개발 관점의 대응 현황입니다. 항목 번호는 ISMS-P 인증기준(2.x 보호대책 요구사항)을 따랐습니다.
> **최종 해석은 인증 심사원/컨설턴트와 확인해야 합니다.**

## 이 시스템이 돕는 통제 (로그 수집·점검 도구로서)

| 항목 | 요구 요지 | 이 시스템의 대응 | 상태 |
|---|---|---|---|
| 2.9.4 로그 및 접속기록 관리 | 로그를 정해진 기간 보관하고 위·변조를 방지 | 중앙 수집, 원본(raw) 보존, 기록 종류별 보관기간(로그 `WLM_RETENTION_DAYS` 365일 — 민감정보 처리 시스템이면 730(`WLM_SENSITIVE_ACCESS_LOG=on` 이면 미달 경고), 감사로그·점검 보고서 1095일, 알림은 로그와 같음 — ADR-040), 법정 최소 미달 경고(기동 로그·화면·점검 보고서), 만료 파기 시 audit_log 기록, **수집 누락 방지**: 늘 오던 로그가 끊긴 채널(PC 는 보내는데 Security 만 멈춤 등)을 화면·점검 보고서에 표시하고 알림 규칙 `stream_silent`로 알림, 규칙이 보는 채널을 보내지 않는 PC(감사 정책·에이전트 설정 누락)를 규칙 표·점검 보고서에 표시(ADR-046), 레코드 하나 때문에 요청 전체가 거절되지 않게 문제 레코드만 원본 그대로 격리·나머지 저장, 서버가 거절한 수집 요청(옛 API 키 등)을 장부에 남겨 화면·점검 보고서에 표시(ADR-044) | Phase 1 |
| 2.9.5 로그 및 접속기록 점검 | 정기 점검과 이상 징후 확인 | 보안 감사 대시보드(로그온 실패 계정·출발지 IP·RDP·계정 잠금·로그 삭제·권한 변경), 웹 서버(IIS)·DB(MSSQL) 대시보드, 분류·사용자·IP 검색. **정기 점검 보고서**: 일간·주간 자동 생성·발송(로그·보안 이벤트·알림 처리·수집 PC·보관·백업, '점검 필요' 요약), 고칠 수 없게 저장, 담당자 **점검 확인**(의견·조치) 기록 (ADR-032) | 구현됨 |
| 2.11.3 이상행위 분석 및 모니터링 | 이상행위 탐지와 대응 | 실시간 화면·대시보드, **알림 규칙 24개**(아래 표): 로그온 실패 급증, 출발지 IP 별 무차별 대입, RDP 무차별 대입, 패스워드 스프레이·없는 계정 대입·여러 서버 원격 로그온(서로 다른 값 수), 계정 잠금, 관리자 그룹 추가, 새 계정·서비스·예약 작업, 감사 로그 삭제·정책 변경, 의심 PowerShell, 악성 코드 탐지, IIS 5xx 급증, SQL Server 로그인 실패·심각 오류, SSH 무차별 대입 → 메일·웹훅·Oracle. 발생·전송 이력은 `alerts`/`alert_deliveries` | 구현됨 |
| 2.11.4 사고 대응 훈련 및 개선 / 2.11.5 사고 대응 | 사고 인지·전파·조치·종료 기록 | 알림 전송 실패 시 재시도, 전송 상태·오류 기록. 사내 DB(Oracle) 연계로 사고관리 시스템에 전달. **알림 처리 기록**: 알림마다 처리 상태(처리 안 됨 → 확인함 → 해결됨)와 처리자·시각, 확인·해결·다시 열기·메모 타임라인(`alert_notes`, 수정·삭제 불가 트리거). 해결·무음은 권한(`alerts.handle`)이 있는 담당자만. **무음**: 점검 중 예상 알림은 전송만 건너뛰고 발생은 기록(무음 사유·기간·설정자 보관, 지금부터 최대 30일). 처리 기록 포함 CSV(엑셀 수식 주입 방지, 잘리면 표시) (ADR-029). **언제까지 계속됐나**: 해결 뒤 다시 생기면 바로 다시 알리고(재발), 재알림 간격 동안 더 들어온 건수·마지막 시각을 알림 상세·다음 알림 본문에 남김(B-35). **종료**: 운영 규칙(`resolve: auto`, PC 수신 끊김)은 조건이 풀리면 '해결됨(자동)'과 처리 기록 '자동 해결'(조건 문구)을 남기고 받은 곳에 해소 통지, 보안 규칙·한 번 나는 이벤트는 사람만 해결, 사람이 다시 연 알림은 엔진이 닫지 않음. 보고서는 자동 해결을 따로 세고 해결 시간 중앙값은 사람이 해결한 것만. 사고관리 연동 키 `dedup_key`·`event_action` (B-35 2단계) | 구현됨 |
| 2.9.2 성능 및 장애관리 | 장애 탐지 | **알림 기능 자체의 장애**(평가 멈춤·전송 실패·규칙 오류)를 화면 상태 띠·`/healthz/alerts`(사내 감시 도구 연동)·점검 보고서로 드러내고, 멈춘 작업은 다시 시작하며 다른 받는 곳으로 알림(감사로그 `alerts.health.*`, ADR-045). **매주 받는 곳마다 정기 시험 전송**(실패하면 다른 곳으로 알림·보고서 '시험 전송 실패', 감사로그 `alerts.test.scheduled`), **Oracle 생존 신호**(1분마다 한 행 — 서버 전체가 멈춘 것을 병원 DB 감시가 잡음) (B-34), PC 상태(온라인/지연/오프라인), 서비스 비정상 종료·디스크 오류 이벤트, `agent_silent` 알림(서버 응답 없음). 화면 조회 쿼리 시간 상한(기본 30초)과 동시 조회 6개 제한 — 느린 검색이 몰려도 수집·알림용 DB 연결 4개는 남김, 끝나지 않은 검색도 접속기록에 남김(ADR-035) | 구현됨 |
| 2.9.6 시간 동기화 | 시스템 시각 동기화 | 저장은 UTC, 발생/수신 시각을 모두 보관해 시계 오차를 확인할 수 있음. 각 PC의 NTP 설정은 운영 정책으로 처리 | 부분 |

| 2.6.x 접근통제 | 접근 경로 제한, 세션 관리 | **구현됨**: **부서별 조회 범위**(사용자 그룹: 분류·PC, 서버에서 적용), **수집 전용 포트(6977 TLS·6976 평문)와 화면 포트 8080 분리**(방화벽 정책 분리), 평문 수집을 닫으면 리스너 자체를 띄우지 않음, 프록시 헤더는 지정한 프록시에서만 믿음(접속 IP 위조 방지), 로그인 필수, 30분 무조작 자동 로그아웃(자동 새로고침은 연장 안 함), 12시간 최대 세션, CSRF 헤더, 로그인 경고문. | 2.7.1 암호정책 적용 | 전송 구간 암호화, 인증정보 보호 | **구현됨 (`WLM_TLS=on`, ADR-036)**: 화면(https)·에이전트 수집(6977) TLS 1.2 이상(1.2 는 ECDHE+AEAD 만, 재협상 끔), 에이전트는 설치 묶음의 CA 와 서버 인증서 이름을 **반드시 확인**(끌 수 없음, 설치 스크립트가 CA 지문 대조), 서버는 에이전트와 같은 OpenSSL 로 확인되지 않는 인증서로는 묶음을 만들지 않음, PC 별 전송 방식 기록과 평문 수집 닫기 스위치, https 세션 쿠키 자동 Secure, 선택 HSTS. 평문으로 남는 곳: 장비 syslog(514), compose 망 안의 수집기 → api(8003). 메일은 STARTTLS/SSL 지원. 화면에서 입력한 비밀번호·웹훅 토큰은 Fernet 암호화 저장, API 로 내보내지 않음. 클라우드 메신저(Slack·Teams·두레이·잔디) 웹훅은 https 만 허용(호스트 기준), 넘김(30x)을 따라가지 않아 인증 헤더가 다른 호스트로 가지 않음, 전송 오류 문구의 토큰은 가려서 기록. 로그인 비밀번호는 scrypt 해시, 세션 토큰은 SHA-256 만 저장 | 장비 TLS syslog(6514, 지원 장비), 운영 서버 실측(B-25) |
| 2.9.4 (자체 로그) | 시스템 자체 접속·변경 기록 | **구현됨** `audit_log` (수정·삭제 불가 트리거): 로그인 성공/실패/잠금/로그아웃/세션 만료, 비밀번호 변경, 사용자 관리, 이벤트 검색 조건(검색 문장 원문 포함)·상세 조회(**누구의 기록인지: 사용자·IP·분류**), 사용자·IP 상위 값 조회(10분에 한 번), CSV 내려받기 사유, 대시보드·알림·환경설정 변경(**알림 설정은 서버에서 파일을 직접 고친 것까지 판본으로 — ADR-043**), **알림 처리(확인·해결·다시 열기·메모)·무음 설정/해제·알림 이력 내려받기**, Oracle 쿼리 실행, 로그 보관·파기. 화면 조회 + CSV 내려받기. 개인정보가 보이는 조회·내려받기는 **기록을 남기지 못하면 거부**(fail-closed, ADR-042) | Phase 2: 로그인, 조회, 설정 변경 전부 기록. audit_log 는 UI에서 조회만 가능 |
| 2.7.2 암호키 관리 | 키 생성·보관·변경 | `WLM_SECRET_KEY`(.env, `openssl rand -hex 32`). DB 백업과 분리 보관. 키 변경 시 비밀값 재입력. **TLS**: 자체 CA 개인키는 api 에 마운트하지 않는 `tls-ca/` 에(오프라인 보관), CA 에 이름 제한(준 DNS·IP 만, 메일 금지)과 용도 제한(서버 인증만) — 키가 새도 다른 서버·메일·코드 서명에 못 씀, 배포된 CA 는 설치 스크립트가 덮어쓰지 않음, 서버 키는 소유자 api 계정·0600, 서버 인증서 2년 갱신(`tls-renew`, 에이전트 재배포 없음), 만료 30일 전부터 매일 경고, TLS 로 옮길 때 수집 키 교체(AIRGAP §7.5) | 키 교체 절차서 |
| 2.9.4 로그 보관·위변조 방지 | 보관기간 동안 안전하게 보관 | **로그 로테이션**: DB 90일 → 압축 보관 파일(SHA-256, 감사로그에 같은 해시, 형식 v2 는 공통 필드 포함 — 복원한 달도 사용자·IP·분류로 검색) → 1년 후 파기·기록. 무결성 확인·복원 기능. **감사로그(권한 부여·변경·말소 기록)는 3년**(안전성 확보조치 기준 제5조③). **외부 저장소 복제**(NAS, 덮어쓰지 않음·만료만 삭제, ADR-047) | DB 밖 위·변조 증명 앵커(B-71) |
| 2.9.3 백업 및 복구 | 백업과 복구 시험 | **구현됨**: `backup` 서비스가 매일 자동 백업(SHA-256, 최근 N개 보관, 파일 권한 600), **매주 임시 DB 에 실제 복원해 확인**(해시·마이그레이션·행 수), 장애 복구 명령(해시 확인 후 복원, 연결 세션이 있으면 거부, 복원 전 DB 안전 사본, 임시 DB 에 복원 후 교체). 결과는 감사로그(`backup.create/failed/verify/restore`)와 화면, 백업 지연·실패 경고. `.env`(키)는 백업과 분리 보관 (ADR-031) | 백업 파일 외부 매체 복제 자동화 (BACKLOG B-17) |
| 2.8.5 소스 프로그램 관리 | 소스 버전관리, 접근통제 | 저장소 구조와 문서 | git 저장소화, 브랜치 보호, 변경 리뷰 |
| 2.8.6 운영환경 이관 | 개발/운영 분리 | override 파일로 개발 설정 분리, 운영은 `-f docker-compose.yml`. **폐쇄망 반입 묶음**: 파일별 SHA-256·이미지 ID·패키지 목록, 설치 시 무결성 검사, 업그레이드 전 자동 백업 (docs/AIRGAP.md, 반입 기록 양식 §6) | 실서버 첫 설치 실측 (BACKLOG B-25) |
| 2.10.x 시스템 보안 | 최소 권한, 보안 설정 | 컨테이너 비 root 실행, 보안 헤더(nosniff, frame DENY), 에이전트 설정 파일 ACL(SYSTEM/Administrators, 600) | 이미지 취약점 점검(Trivy, Apache 2.0) |

| 제8조① | 접속한 자(정보주체 제외)의 접속기록 1년 이상, 5만명 이상·고유식별·민감정보 처리 시스템은 2년 이상 | 감사로그 3년(ADR-040). 진료정보를 다루는 설치면 `WLM_SENSITIVE_ACCESS_LOG=on`(로그 보관 730일 미만 경고) |
| 제8조② | (2026-10-31부터) 접속기록·다운로드 상황의 **점검 주기·방법·사후조치절차를 내부 관리계획으로** 정하고 이행. '월 1회 이상'·'다운로드 사유 반드시 확인' 문구는 빠짐 | 점검 보고서(일간·주간)·감사로그 화면. 내부 관리계획에 주기와 CSV 내려받기 사유 확인(ADR-042)을 사후조치로 적기를 권합니다. 주기 선택형 결과서는 B-72 |
| 제8조③ | 접속기록이 위·변조·도난·분실되지 않도록 안전하게 보관하는 **조치**(방법은 정하지 않음) | 수정·삭제 금지 트리거, 보관 파일 SHA-256, 외부 저장소 복제(ADR-047). DB 밖 해시 앵커는 B-71 |
| 제5조③ | 권한 부여·변경·말소 내역 최소 3년 | 감사로그 3년(ADR-040), 관리 권한 부여 알림(B-36) |
| 제4조①12호 | (2026-10-31부터) 내부 관리계획에 출력·복사 시 안전조치 | CSV 내려받기 사유·행 수 기록(ADR-042) |
| 제6조①2호 | 접속 IP 등을 분석해 유출 시도 탐지·대응 | 알림 규칙(출발지 IP 기준 무차별 대입·패스워드 스프레이·한 계정의 여러 서버 원격 접속 등), IP 검색·상위 값 |
| 제16조·제17조 | 인사정보 연계, 접속기록 자동 분석·소명 — **보호위원회가 지정한 공공시스템만** | 해당 여부는 병원 확인(B-39) |

- **의료법 제23조④ (EMR 열람 접속기록, 2026-12-10 시행, 법률 제21776호):** 보관 장비는 EMR 의 이력관리 장비입니다(시행규칙 개정안 제16조②, 입법예고 단계). 이 시스템은 EMR 접속기록을 받지 않으며, 맡을 범위는 병원 답변 뒤 정합니다(ADR-048, BACKLOG B-39·B-76). (https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=286719&efYd=20261210)

## 심사 때 보여줄 수 있는 증적

- **외부 저장소 복제 (2.9.3·2.9.4, ADR-047):** 환경설정 > 로그 보관의 '외부 저장소 복제'(마지막 복제·복제본 수), 감사로그 '외부 저장소 복제'. 새 파일만 복사·해시 확인하고 덮어쓰지 않으며 만료된 것만 지웁니다(랜섬웨어로 원본이 바뀌어도 복제본 보존).
- **백업·복구 시험 (2.9.3):** 환경설정 > 로그 보관의 'DB 백업 · 복구 시험'(마지막 백업·복구 시험 결과), 감사로그 `backup.create`·`backup.verify`(복원한 행 수 포함)·`backup.failed`·`backup.restore`, `backups/*.json`(백업마다 해시·행 수)
- **보관:** 환경설정 > 로그 보관 화면(정책·파티션·보관 파일), `audit_log` 의 `retention.archive_partition`(해시 포함)·`retention.drop_partition`·`retention.delete_archive`
- **무결성:** '보관 파일 무결성 확인' 결과(`retention.verify_archives`), 감사로그 append-only 트리거(`server/migrations/003_auth.sql`)
- **접속기록:** 감사 로그 화면 CSV — 로그인 이력, 이벤트 검색·조회 기록(누가·언제·어디서·무엇을). 시간 상한으로 멈춘 검색도 `timeout_sec` 과 함께 남습니다.
  - 서버 컨테이너 로그(`docker logs`, 파일당 50MB × 5개 회전)에도 요청 주소(검색 조건 포함)가 남습니다. 서버 접속 권한자만 볼 수 있게 관리합니다.
- **계정 관리:** 사용자 화면(역할, 마지막 로그인, 비밀번호 변경일, 잠금 상태)
- **정기 점검 (2.9.5):** '점검 보고서' 화면 — 일간·주간 보고서 이력, 점검 필요 항목, 점검 확인(누가·언제·의견), 인쇄용 문서(PDF 저장). 감사로그 `report.create`(내용 해시, 만든 사람 IP)·`report.deliver`(자동 발송 결과)·`report.review`·`report.send`, 받는 곳의 메일. 보고서마다 받는 곳별 전송 기록(다시 보내도 첫 발송 결과가 남음). 보고서는 DB 트리거로 내용 수정·삭제를 막습니다(`server/migrations/011_reports.sql`). 보안 감사 대시보드 화면, 검색 결과(URL로 재현 가능)
- **변경 이력:** `config/dashboards`, `config/alerts.yaml` 의 git 이력과 `audit_log` 의 `dashboard.save`, `alerts.config.save` 기록(내용 해시 포함)
- **이상행위 대응:** 알림 화면의 이력(발생 시각, 규칙, 대상 PC, 전송 성공 여부), 메일·사내 DB 수신 기록
- **사고 대응 기록 (2.11.5):** 알림 이력 CSV(처리 상태·확인한 사람·해결한 사람·시각·처리 기록 전체), 알림 상세의 처리 기록 타임라인, 감사로그 `alerts.ack`·`alerts.resolve`·`alerts.reopen`·`alerts.note`·`alerts.export`. 처리 기록은 DB 트리거로 수정·삭제·TRUNCATE 할 수 없습니다(`server/migrations/009_alert_handling.sql`, `010_alert_notes_no_truncate.sql`). CSV 는 로그에서 온 값이 수식으로 실행되지 않게 처리합니다(`app/csvexport.py`)
- **알림 무음 이력:** 알림 > 무음 탭(범위·기간·사유·설정자·일찍 해제한 사람·보내지 않은 알림 수), 감사로그 `alerts.silence.create`·`alerts.silence.end`. 무음 중에 발생한 알림도 이력에 '무음'으로 남습니다
- **권한 부여 내역:** 사용자 > 사용자 그룹 화면(권한·범위·구성원), 감사로그 `user_group.save/delete`
- **수집 누락 (2.9.4, ADR-044):** 수집 PC 화면(관리자)의 '수집 거절·격리' — 거절된 수집 요청(보낸 IP·상태·사유·횟수·처음/마지막)과 저장하지 못해 격리한 레코드(원본 열람은 접속기록 `events.quarantine.view`). 점검 보고서 '수집 PC' 절과 '점검 필요'.
- **규칙 변경 이력:** 감사로그 `alerts.rule.save/delete/toggle`(규칙 이름·SID·파일 해시)
- **관리자 행위 점검 (2.5.5·2.9.5, B-36):** 받는 곳을 약하게 하는 저장·관리 권한 부여·보관 파일 복원은 '관리 작업 알림'으로 다른 사람에게 바로 알리고(무음 불가),
  점검 보고서 '관리 작업 요약'에 기간의 관리 작업 수(권한·계정, 알림 규칙·무음, 받는 곳, 보관·복원, 내려받기)를 남깁니다.
- **알림 설정 변경 관리 (2.9.1·2.9.5, ADR-043):** 감사로그 '알림 설정 변경(판본)' — 적용한 설정마다 판본(`alert_config_versions`, 고칠 수 없음):
  방법(화면·서버 파일 직접 수정·꺼져 있는 동안의 수정)·누가·직전 판본과의 차이·탐지 약화 여부. 탐지를 약하게 하는 변경·넓은 무음은 바뀌기 전
  받는 곳에 '알림 설정 변경' 알림으로 바로 전파되고(무음으로 막을 수 없음), 점검 보고서 '점검 필요'에 다시 나옵니다(관리자 행위 점검).
- **에이전트 배포 기록:** 감사로그 `agents.package.download`(대상·서버 주소, TLS 면 `tls`·인증서 이름·CA 지문, 키 값은 기록하지 않음)
- **전송 구간 암호화 (2.7.1):** 수집 PC 화면의 '연결' 칸(PC 별 TLS·평문, 평문 PC 수), `python -m app.cli tls-status` 출력(인증서 이름·만료·CA 지문), 서버 기동 로그의 리스너 줄('화면 8000(TLS) · 수집 8002(TLS) …'), 방화벽 변경 기록(6977 허용·6976 삭제)
- **수집 PC 삭제 기록:** 감사로그 `agent.delete` — PC 마다 한 줄, 지운 행 요약(IP·최초/마지막 수신·누적 건수·설정 버전). 이벤트 로그는 지우지 않음(보관 정책으로만 삭제)
- **통제 매핑:** 알림 화면의 규칙 목록에 규칙마다 `ISMS 2.x.x`, `MITRE Txxxx` 태그가 보입니다(`config/alerts.yaml` 의 `tags`).
