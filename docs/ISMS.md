# ISMS(-P) 대응 메모

> 이 문서는 개발 관점의 대응 현황입니다. 항목 번호는 ISMS-P 인증기준(2.x 보호대책 요구사항)을 따랐습니다.
> **최종 해석은 인증 심사원/컨설턴트와 확인해야 합니다.**

## 이 시스템이 돕는 통제 (로그 수집·점검 도구로서)

| 항목 | 요구 요지 | 이 시스템의 대응 | 상태 |
|---|---|---|---|
| 2.9.4 로그 및 접속기록 관리 | 로그를 정해진 기간 보관하고 위·변조를 방지 | 중앙 수집, 원본(raw) 보존, `WLM_RETENTION_DAYS` 기본 365일, 만료 파기 시 audit_log 기록 | Phase 1 |
| 2.9.5 로그 및 접속기록 점검 | 정기 점검과 이상 징후 확인 | 보안 감사 대시보드(로그온 실패 계정·출발지 IP·RDP·계정 잠금·로그 삭제·권한 변경), 웹 서버(IIS)·DB(MSSQL) 대시보드, 분류·사용자·IP 검색 | 구현됨. 정기 점검 보고서 자동 발송은 BACKLOG |
| 2.11.3 이상행위 분석 및 모니터링 | 이상행위 탐지와 대응 | 실시간 화면·대시보드, **알림 규칙 20개**(아래 표): 로그온 실패 급증, 출발지 IP 별 무차별 대입, RDP 무차별 대입, 계정 잠금, 관리자 그룹 추가, 새 계정·서비스·예약 작업, 감사 로그 삭제·정책 변경, 의심 PowerShell, 악성 코드 탐지, IIS 5xx 급증, SQL Server 로그인 실패·심각 오류, SSH 무차별 대입 → 메일·웹훅·Oracle. 발생·전송 이력은 `alerts`/`alert_deliveries` | 구현됨 |
| 2.11.4 사고 대응 훈련 및 개선 / 2.11.5 사고 대응 | 사고 인지·전파 | 알림 전송 실패 시 재시도, 전송 상태·오류 기록. 사내 DB(Oracle) 연계로 사고관리 시스템에 전달 | 구현됨 |
| 2.9.2 성능 및 장애관리 | 장애 탐지 | PC 상태(온라인/지연/오프라인), 서비스 비정상 종료·디스크 오류 이벤트, `agent_silent` 알림(서버 응답 없음) | 구현됨 |
| 2.9.6 시간 동기화 | 시스템 시각 동기화 | 저장은 UTC, 발생/수신 시각을 모두 보관해 시계 오차를 확인할 수 있음. 각 PC의 NTP 설정은 운영 정책으로 처리 | 부분 |

## 이 시스템 자체가 갖춰야 할 통제

| 항목 | 요구 요지 | 현재 | 계획 |
|---|---|---|---|
| 2.5.1~2.5.4 계정·인증·비밀번호 | 사용자 식별, 안전한 인증, 비밀번호 정책 | **구현됨**: 개인 계정, scrypt 해시, 3종 8자/2종 10자 정책, 임시 비밀번호 첫 로그인 변경, 90일 변경 주기, 5회 실패 10분 잠금, 계정 존재 여부를 숨기는 실패 문구 | 사내 SSO 연동(필요 시, ADR-013) |
| 2.5.5 특수 계정 및 권한 | 관리자 권한 최소화 | **구현됨**: 관리자/조회자 분리, 마지막 관리자 강등·자기 자신 비활성화 금지, 관리자 전용 기능은 서버에서 차단 | 정기 권한 검토(2.5.6)는 '사용자' 화면 + 감사로그로 |
| 2.6.x 접근통제 | 접근 경로 제한, 세션 관리 | **구현됨**: 로그인 필수, 30분 무조작 자동 로그아웃(자동 새로고침은 연장 안 함), 12시간 최대 세션, CSRF 헤더, 로그인 경고문. DB 포트 미노출(운영) | 접근 IP 제한(리버스 프록시) |
| 2.7.1 암호정책 적용 | 전송 구간 암호화, 인증정보 보호 | 수집은 평문 HTTP. 메일은 STARTTLS/SSL 지원. 화면에서 입력한 비밀번호·웹훅 토큰은 Fernet 암호화 저장, API 로 내보내지 않음. 로그인 비밀번호는 scrypt 해시, 세션 토큰은 SHA-256 만 저장 | Phase 2: 리버스 프록시(Caddy/Nginx, 오픈소스) TLS, 에이전트 `tls: on` |
| 2.9.4 (자체 로그) | 시스템 자체 접속·변경 기록 | **구현됨** `audit_log` (수정·삭제 불가 트리거): 로그인 성공/실패/잠금/로그아웃/세션 만료, 비밀번호 변경, 사용자 관리, 이벤트 검색 조건·상세 조회, 대시보드·알림·환경설정 변경, Oracle 쿼리 실행, 로그 보관·파기. 화면 조회 + CSV 내려받기 | Phase 2: 로그인, 조회, 설정 변경 전부 기록. audit_log 는 UI에서 조회만 가능 |
| 2.7.2 암호키 관리 | 키 생성·보관·변경 | `WLM_SECRET_KEY`(.env, `openssl rand -hex 32`). DB 백업과 분리 보관. 키 변경 시 비밀값 재입력 | 키 교체 절차서 |
| 2.9.4 로그 보관·위변조 방지 | 보관기간 동안 안전하게 보관 | **로그 로테이션**: DB 90일 → 압축 보관 파일(SHA-256, 감사로그에 같은 해시) → 1년 후 파기·기록. 무결성 확인·복원 기능 | 보관 파일을 별도 매체/스토리지로 복제 |
| 2.9.3 백업 및 복구 | 백업과 복구 시험 | `pg_dump` 절차 문서화(PROJECT.md §13), `archive/`·`.env` 백업 | 백업 자동화 스크립트, 분기별 복구 시험 기록 |
| 2.8.5 소스 프로그램 관리 | 소스 버전관리, 접근통제 | 저장소 구조와 문서 | git 저장소화, 브랜치 보호, 변경 리뷰 |
| 2.8.6 운영환경 이관 | 개발/운영 분리 | override 파일로 개발 설정 분리, 운영은 `-f docker-compose.yml`. **폐쇄망 반입 묶음**: 파일별 SHA-256·이미지 ID·패키지 목록, 설치 시 무결성 검사, 업그레이드 전 자동 백업 (docs/AIRGAP.md, 반입 기록 양식 §6) | 실서버 첫 설치 실측 (BACKLOG B-25) |
| 2.10.x 시스템 보안 | 최소 권한, 보안 설정 | 컨테이너 비 root 실행, 보안 헤더(nosniff, frame DENY), 에이전트 설정 파일 ACL(SYSTEM/Administrators, 600) | 이미지 취약점 점검(Trivy, Apache 2.0) |

## 수집 측 권장 설정 (각 Windows PC)

| 항목 | 권장 |
|---|---|
| 감사 정책 | 로그온/로그오프, 계정 관리, 권한 사용, 정책 변경, 시스템 이벤트의 성공·실패 감사를 GPO로 켭니다 |
| 추가 감사 (규칙 팩용) | 보안 그룹 관리(4732), 기타 개체 액세스(예약 작업 4698), 보안 시스템 확장(서비스 설치 4697), Kerberos 인증(4771) 감사를 켭니다 |
| PowerShell | GPO '스크립트 블록 로깅 사용'(4104) — '의심스러운 PowerShell 실행' 규칙에 필요합니다 |
| IIS·SQL Server | IIS 로그는 W3C 형식, 하루 단위 롤오버. SQL Server 는 '로그인 감사: 실패한 로그인만' 이상으로 둡니다(18456 기록) |
| 보안 로그 크기 | 수집 지연에 대비해 로컬 보안 로그 최대 크기를 충분히 키웁니다 (예: 256MB 이상) |
| 시각 | 도메인 계층 NTP(w32time)를 씁니다 |
| 에이전트 설정 파일 | API 키가 들어 있으므로 SYSTEM/Administrators 만 읽게 합니다 (install.ps1이 적용) |

## 심사 때 보여줄 수 있는 증적

- **보관:** 환경설정 > 로그 보관 화면(정책·파티션·보관 파일), `audit_log` 의 `retention.archive_partition`(해시 포함)·`retention.drop_partition`·`retention.delete_archive`
- **무결성:** '보관 파일 무결성 확인' 결과(`retention.verify_archives`), 감사로그 append-only 트리거(`server/migrations/003_auth.sql`)
- **접속기록:** 감사 로그 화면 CSV — 로그인 이력, 이벤트 검색·조회 기록(누가·언제·어디서·무엇을)
- **계정 관리:** 사용자 화면(역할, 마지막 로그인, 비밀번호 변경일, 잠금 상태)
- **정기 점검:** 보안 감사 대시보드 화면, 검색 결과(URL로 재현 가능)
- **변경 이력:** `config/dashboards`, `config/alerts.yaml` 의 git 이력과 `audit_log` 의 `dashboard.save`, `alerts.config.save` 기록(내용 해시 포함)
- **이상행위 대응:** 알림 화면의 이력(발생 시각, 규칙, 대상 PC, 전송 성공 여부), 메일·사내 DB 수신 기록
- **통제 매핑:** 알림 화면의 규칙 목록에 규칙마다 `ISMS 2.x.x`, `MITRE Txxxx` 태그가 보입니다(`config/alerts.yaml` 의 `tags`).

| ISMS 항목 | 규칙 |

| 2.10.x 시스템 보안·악성코드 | 새 서비스 설치(2.10.1), 백신 악성 코드 탐지(2.10.9) |
| 2.11.3 이상행위 | 로그온 실패 급증, 무차별 대입(출발지 IP), 원격 데스크톱 무차별 대입, SQL Server 로그인 실패 급증, Linux SSH 무차별 대입, 의심스러운 PowerShell 실행, 예약 작업 생성 |
